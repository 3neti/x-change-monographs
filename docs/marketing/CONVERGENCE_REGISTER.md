# Marketing Visual Convergence Register

## Purpose

This register connects prototype exploration to a later production visual language. It records which visual characteristics survive reader testing, where each characteristic originated, and what observed comprehension benefit supports preserving it.

The register is evidence-led. It is not a preference list, style mood board, or declaration of a winning prototype.

## Entry rule

Add an evidence entry only when a completed reader study supplies:

- a specific visual characteristic;
- its source prototype or control;
- an observed participant benefit;
- traceable evidence references;
- the study conditions and sample denominator; and
- a stated confidence or limitation.

Internal expectations, design-team judgments, and participant preferences must not be entered as observed benefits.

## Status vocabulary

| Status | Meaning |
| --- | --- |
| Proposed from evidence | Recorded evidence supports evaluation in convergence work |
| Retest required | Evidence is promising but inconsistent or condition-dependent |
| Preserve | Repeated evidence supports retention in the production-language study |
| Reject | Evidence shows material confusion or no useful benefit |
| Deferred | Evidence is insufficient or the characteristic is outside the current surface |

None of these statuses selects a production identity.

## Convergence review

A later convergence review should ask:

1. Which characteristics improve comprehension across more than one condition?
2. Which characteristics improve memory without weakening doctrine?
3. Which characteristics survive label removal and scale change?
4. Which benefits are unique to one surface?
5. Which combinations can be tested without creating a visually incoherent ninth direction?

Any combined study must be versioned as a new prototype derived from traceable evidence. It must pass the full validation profile before production use.
