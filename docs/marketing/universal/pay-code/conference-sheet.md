# Pay Code in 30 Seconds

## Send money without asking where they bank.

> A Pay Code lets someone receive money without requiring the sender to know their bank account, e-wallet, or financial provider.

## Authorize → Share → Receive

**Authorize** — Define the outcome, recipient, amount or purpose, and conditions.

**Share** — Represent the authorized instruction as a Pay Code and communicate it to the recipient.

**Receive** — Present the Pay Code through a supported journey so a participating financial provider can complete the approved transaction.

**Primary illustration:** `VIS-001 Core Pay Code`

**Alt text:** A sender who does not know the recipient's bank or wallet authorizes an outcome. A responsible institution issues a Pay Code, the sender shares it, the recipient chooses among available supported destinations, conditions are checked, and a participating financial provider completes the approved transaction.

> **The Pay Code carries the instruction—not the money.**

## Why it matters

The sender does not need the recipient's financial destination in advance. The recipient can use an available supported destination. Participating institutions retain the authority, controls, settlement relationships, and evidence behind the journey.

## One workflow is enough to begin

Payroll. Benefits. Claims. Refunds. Remittance. Assistance.

**Bring one payment or disbursement workflow.**

Together, we can examine whether Pay Code offers a simpler way to communicate and complete the authorized instruction.

> Money should adapt to people. Not the other way around.
