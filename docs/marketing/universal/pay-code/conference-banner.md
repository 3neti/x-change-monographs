# Send money without asking where they bank.

## Generate. Share. Claim.

**Primary composition:** `VIS-001 Core Pay Code Journey`

**Alt text:** A responsible institution generates a Pay Code for an intended payment, the sender shares it with the recipient, and the recipient claims it through one available supported destination they choose.

> **Send a Pay Code. The recipient chooses where to receive.**

No bank account, e-wallet, or provider details needed upfront.

## Composition notes — not publication copy

- Design for comprehension from several metres away within five to ten seconds.
- Let VIS-001 occupy the dominant field.
- Preserve exactly three first-level moments: Generate, Share, Claim.
- Keep the same Pay Code visually continuous across the journey.
- Show Recipient Choice as a bounded detail inside Claim.
- Use the headline, three verbs, primary message, and supporting line as the complete public copy.
- Keep institutional authority visible within Generate but visually quiet.
- Keep validation and completion visible within Claim but visually quiet.
- Include only the approved x-change identity treatment; do not introduce provider or institution logos.
- Do not add use cases, implementation language, architecture, prices, testimonials, availability claims, or multiple calls to action.
- A renderer may arrange VIS-001 vertically or horizontally according to the banner proportions, but it may not redefine the composition.
- Do not add a QR code or destination until its purpose and target have been separately governed and verified.
