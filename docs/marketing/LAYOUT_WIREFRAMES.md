# Marketing Layout Wireframes

## Purpose

These wireframes show how the canonical visual story may occupy different publication formats without being rebuilt or reinterpreted. They specify hierarchy and reading order, not dimensions, typography, color, or artwork.

All wireframes preserve one rule:

```text
The illustration explains.
The copy confirms.
```

## Composition hierarchy

Use the following hierarchy unless a smaller format requires compression:

1. Human problem or headline.
2. VIS-001 Core Pay Code Journey.
3. Canonical primary message.
4. One supporting line.
5. One invitation.
6. Restrained boundary text only where the medium requires it.

ILL-001 may precede VIS-001 when the publication has room to establish the problem. ILL-006, VIS-002, VIS-003, and VIS-004 follow the core journey and must not compete with it.

## WF-001 — Universal Pay Code Flyer

Fifteen seconds, viewed at arm’s length or while passing.

### Portrait wireframe

```text
│ │                                     │ │

│ │                                     │ │
│ │  GENERATE  →  SHARE  →  CLAIM       │ │
│ │                         └ choice     │ │
│ │                                     │ │
│ └─────────────────────────────────────┘ │
│                                         │
│ PRIMARY MESSAGE                         │
│ invitation                         mark │
└─────────────────────────────────────────┘
```

### Hierarchy

- VIS-001 occupies the largest uninterrupted field.
- The headline and supporting line act as one compact opening block.
- The primary message confirms the visual argument after it has been seen.
- One invitation closes the page.

### Responsive alternative

For narrow portrait space, stack Generate, Share, and Claim vertically. Do not shrink them into an illegible horizontal strip.

## WF-002 — Universal Pay Code Tri-fold Brochure

### Reading condition

The cover must earn opening; each panel must answer one question.

### Outside spread

```text
┌────────────────┬────────────────┬────────────────┐
│ PANEL 6        │ PANEL 1 COVER  │ PANEL 2        │
│ Everyday uses  │ Human problem  │ Unknown        │
│ VIS-003/004    │ ILL-001        │ destination    │
│ invitation     │ primary message│ ILL-001 detail │
└────────────────┴────────────────┴────────────────┘
```

### Inside spread

```text
┌────────────────┬────────────────┬────────────────┐
│ PANEL 3        │ PANEL 4        │ PANEL 5        │
│ GENERATE       │ SHARE          │ CLAIM          │
│ ILL-002        │ ILL-003        │ ILL-004        │
│                │                │ └ ILL-005      │
└────────────────┴────────────────┴────────────────┘
```

### Hierarchy

- The front cover establishes the human problem, not architecture.
- Opening the brochure reveals Generate → Share → Claim as one uninterrupted spread.
- Recipient Choice remains inside the Claim panel.
- Everyday applications close the journey without becoming a feature catalogue.

### Fold rule

The physical imposition may change with printer convention, but the reader’s unfolded sequence must remain Generate → Share → Claim from left to right.

### Reading condition

Progressive disclosure over approximately 60–120 seconds.

### Page wireframe

```text

├─────────────────────────────────────────┤
│ HOW                                     │
│ ILL-002 Generate                        │
│             ↓                           │
│ ILL-003 Share                           │
│             ↓                           │
│ ILL-004 Claim                           │
│       └── ILL-005 Recipient Choice      │
├─────────────────────────────────────────┤
│ WHO SUPPORTS IT                         │
│ ILL-006 Participating Institutions      │
├─────────────────────────────────────────┤
│ WHERE IT MAY APPLY                      │
│ VIS-003 + VIS-004                       │
├─────────────────────────────────────────┤
│ ONE INVITATION                          │
└─────────────────────────────────────────┘
```

### Hierarchy

- The hero must communicate the complete public story without scrolling.
- Later sections expand one question at a time: Why, How, Who, Where.
- ILL-006 appears only after the human journey.
- Everyday-use tiles demonstrate breadth but do not add service claims.

### Responsive rule

On narrow screens, stack all frames in canonical order. Never hide essential meaning behind hover, autoplay, or interaction.

## WF-007 — Short Animation Storyboard

### Reading condition

Twenty to forty-five seconds, understandable without narration.

| Time | Frame | Visual action | Optional words |
| ---: | --- | --- | --- |
| 0–4s | Human problem | Known sender and recipient; destination remains unknown | Where do they receive? |
| 4–10s | Generate | Intended payment becomes a Pay Code inside the institutional frame | Generate. |
| 10–16s | Share | The same credential moves through one ordinary channel | Share. |
| 16–26s | Claim | Recipient presents the credential; supported choices appear within the scene | Claim. |
| 26–32s | Choice and completion | One path is selected, validated, and completed | The recipient chooses. |
| 32–40s | Closing | Compact VIS-001 and primary message | Send a Pay Code. |

Animation may reveal nested detail, but it may not convert authorization or recipient choice into additional title cards or first-level steps.

| Flyer | VIS-001 | VIS-001 | None | 1 |

## Wireframe validation

Before a format proceeds to visual prototyping, confirm that:

- the eye encounters the human idea before institutional architecture;
- VIS-001 remains the dominant visual argument;
- labels are unnecessary for understanding actor movement;
- Recipient Choice remains visibly nested within Claim;
- no layout implies that the Pay Code contains or moves money;
- use cases remain examples rather than service claims; and
- removing all paragraphs still leaves the central idea understandable.

These wireframes are conceptual publication sources. They are not final layouts, production templates, or renderer specifications.
