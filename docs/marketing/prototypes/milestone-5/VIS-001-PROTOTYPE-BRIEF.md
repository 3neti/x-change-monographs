# VIS-001 Prototype Brief

## Objective

Explore eight genuinely different visual interpretations of VIS-001 while holding meaning constant.

The work tests semantic resilience. It does not select final illustration style, typography, color, branding, or publication treatment.

## Fixed meaning

Every prototype must communicate:

```text
Generate → Share → Claim
                     └ choice inside Claim
```

The intended payment exists before the Pay Code. The credential is generated within a governed context, moves through an ordinary communication path, stops with the recipient, and is presented during Claim. The recipient selects one available supported destination. A participating provider completes the financial movement. Money never moves inside the Pay Code.

## Fixed semantic sequence

1. **Intention** — a payment or disbursement purpose exists.
2. **Generate** — the authorized instruction becomes a Pay Code.
3. **Share** — the same credential moves to the intended recipient.
4. **Claim** — movement stops; the recipient acts.
5. **Choice** — a bounded set opens inside Claim.
6. **Completion** — one destination remains selected and one completion follows.

Intention, Choice, and Completion are necessary visual meaning. They are not additional public steps.

## Prototype invariants

- Three and only three first-level moments.
- One visually continuous Pay Code.
- One intended recipient.
- Choice nested inside Claim.
- Two or three neutral supported destinations at most.
- One selected path and one completion.
- Institutional responsibility present but secondary.
- Credential movement distinct from financial movement.
- Grayscale comprehension without brand color.
- A visible `NON-PRODUCTION PROTOTYPE` designation.

## Prohibited interpretations

No prototype may imply:

- stored value, wallet balance, or money inside the Pay Code;
- self-created or arbitrary value;
- payment completion merely because the code was shared;
- universal provider participation;
- x-change as bank, authority, or custodian;
- choice before Claim;
- several selected destinations;
- duplicated redemption or payout; or
- money traveling through a communication channel.

## Common prototype frame

Each SVG uses a shared study frame so comparison remains possible:

- neutral grayscale only;
- one wide composition field;
- visible Generate, Share, and Claim labels;
- explicit nested Choice detail;
- quiet completion marker;
- no final brand mark;
- no final typography claim; and
- accessible title and description.

The common frame is an evaluation convenience, not a production format.

## Direction set

| ID | Visual family | Primary hypothesis |
| --- | --- | --- |
| D01 | Flat Geometric | Primitive geometry produces immediate cross-format comprehension |
| D02 | Rounded Friendly | Soft human forms make recipient agency and Claim emotionally legible |
| D03 | Transit Map | A single route makes order and memory exceptionally clear |
| D04 | Editorial Line | Sparse narrative scenes preserve human nuance without UI conventions |
| D05 | Pictographic Wayfinding | Signage-like symbols maximize distance recognition |
| D06 | Modular Card | Bounded moments make complex nested meaning easy to scan and adapt |
| D07 | Isometric System | Layered platforms distinguish human action from institutional support |
| D08 | Minimal Institutional | Extreme restraint creates executive credibility and semantic focus |

## Required review questions

For every direction ask:

- Where does the eye go first?
- What appears to move?
- What does the Pay Code appear to contain?
- Does the recipient visibly act?
- Does Claim feel like the payoff?
- Is Choice clearly nested?
- Is exactly one destination selected?
- Does the institutional layer remain secondary?
- Can the journey be redrawn from memory?
- What can be removed?

## Validation status

The design team has completed an internal semantic preflight only. No first-reader results are claimed. The [Reader-Testing Protocol](READER-TESTING-PROTOCOL.md) prepares later evidence-based evaluation.

## Stop condition

Milestone 5 ends with informed narrowing. It does not approve production artwork or a permanent x-change visual identity.
